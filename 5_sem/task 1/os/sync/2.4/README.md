## 2.4. Простые CAS-спинлок и futex-мьютекс

```bash
cd 2.4
make
/usr/bin/time -v ./locks spin 4 1000000
/usr/bin/time -v ./locks mutex 4 1000000
```

Аргументы: тип блокировки, число потоков, число увеличений счётчика каждым потоком. Общий ресурс — обычная переменная counter. Операция counter++ выполняется только внутри самодельной блокировки.

Ожидается:

```text
counter=4000000 expected=4000000: OK
```

### CAS

Compare-and-swap атомарно сравнивает значение с ожидаемым и при совпадении заменяет его. У нас 0 — свободно, 1 — занято. Только один поток может успешно изменить 0 на 1.

В C используется atomic_compare_exchange_strong_explicit. Пара acquire при захвате и release при освобождении обеспечивает видимость изменений защищённого счётчика между потоками.

### Спинлок

Постоянно повторяет CAS, пока не захватит блокировку. Освобождение записывает 0. Это намеренно простая реализация без оптимизаций, гарантий справедливости и рекурсивного захвата.

### Мьютекс

Сначала пробует CAS. При неудаче вызывает FUTEX_WAIT_PRIVATE и ждёт, пока слово равно 1. После пробуждения повторяет CAS: пробуждение ещё не означает владение блокировкой.

Освобождение записывает 0, затем вызывает FUTEX_WAKE_PRIVATE для одного ожидающего потока. Для простоты wake выполняется при каждом unlock, даже если ожидающих нет. Это увеличивает расходы и отличается от оптимизированного pthread_mutex.

Futex проверяет значение и переводит поток в ожидание согласованно: если между неудачным CAS и ожиданием блокировка уже освободилась, FUTEX_WAIT вернёт EAGAIN вместо сна на устаревшем состоянии. EINTR также приводит к повторной попытке.

Само слово блокировки находится в пользовательской памяти; futex предоставляет механизм ожидания и пробуждения через ядро. Эта реализация рассчитана на Linux с 32-битным atomic_int и предназначена для потоков одного процесса.

### Сравнение

Повторить с 1, 2, 4 потоками при одинаковом числе увеличений. Смотреть корректность счётчика, elapsed, user, system и CPU%. Самодельный спинлок может быстро работать при коротком ожидании, но тратит CPU при конкуренции. Простой мьютекс может расходовать больше system из-за futex и безусловного wake. Заранее утверждать победителя нельзя.


Для сборки и проверки futex нужен Linux. На Mac этот вариант не запускался.
